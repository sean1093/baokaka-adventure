# 寶咖咖勇者團 — 設計文件

**日期**：2026-09-06
**狀態**：已實作
**前作**：[2026-09-01 寶咖咖與摩卡貓的冒險](./2026-09-01-baokaka-adventure-design.md)（尋物點點看，本文簡稱「找找看」）

## 1. 目標

在同一個網址下加入第二個遊戲：一個給**一般玩家**（大人、小孩，不特別遷就長輩）玩的簡單回合制 RPG。原本的首頁改成**遊戲選單**，列出找找看與這個新遊戲，各自顯示存檔進度。

成功標準：一個沒看過任何說明的人，打開連結、點進勇者團，能在一次搭車的時間內打完第一章，並且在第三章之後的頭目戰真的需要看敵人的動作、決定要打還是要防禦或補血。

### 非目標

- 沒有帳號、後端、排行榜、多人（同前作）
- 沒有裝備、商店、金錢、隨機地圖：內容固定，才能用模擬器調平衡
- 沒有即時操作：一切都是點按鈕，沒有計時
- 只有繁體中文；只支援直向

## 2. 玩法

**回合制 2 對 1～3。** 寶咖咖與摩卡貓是固定隊伍，對上「搗蛋鬼」。玩家每回合替兩位英雄各選一個動作，然後敵人依序行動。

三個互相咬合的機制，缺一個就沒有決策：

1. **敵人意圖公開。** 每個敵人頭上永遠顯示它下一步要做什麼（招式、預估傷害、打誰或全體）。大招前一回合一定是「蓄力」，所以「要不要防禦」是玩家看得到、算得出的決定。單體攻擊的目標在意圖形成時就決定好（`FoeState.aim`），因此只有被瞄準的英雄需要防禦。
2. **共用元氣（0～5）。** 基本攻擊與防禦 +1，招式花 1～3。攻擊累積、放招消費，兩位英雄共用一條，所以「摩卡貓先撲擊還是留給寶咖咖大哭」是每回合的取捨。
3. **血量跨戰鬥延續。** 一章四站（戰鬥、戰鬥、營地、頭目），HP 不會自動回滿，只有升級、營地睡覺、過章時回滿。道具與補血招式的價值由此而來。

輸了不是結束：回到本章第一站、HP 回滿、經驗值與道具全部保留。夠痛（要重打兩場），但不會讓人放棄。

### 英雄

| | 寶咖咖（坦克／輔助） | 摩卡貓（輸出） |
|---|---|---|
| 血量 | 60 + 10／級 | 45 + 8／級 |
| 攻擊 | 8 + 2／級 | 11 + 3／級 |
| Lv1 | 丟積木（單體，元氣 +1）、大哭（2 元氣，全體 0.8 倍，一半機會嚇到）、防禦 | 貓抓（單體，元氣 +1，25% 暴擊）、撲擊（1 元氣，單體 1.8 倍）、防禦 |
| Lv2 | | 呼嚕嚕（兩人回復 12%，元氣 +2） |
| Lv3 | 抱抱（1 元氣，一個夥伴回復 40%，可扶起倒下的） | |
| Lv4 | | 貓草狂暴（3 元氣，亂抓 4 下 × 0.75 倍） |
| Lv5 | 無敵尖叫（3 元氣，全體 1.5 倍，必定嚇到） | |
| Lv6 | 最高等級 | 最高等級 |

「嚇到」= 該敵人跳過下一次行動（不推進招式循環）。「防禦」= 到本回合結束前受傷減半。倒下的英雄可以被抱抱或奶瓶扶起；戰鬥打贏時倒下的英雄以 25% 血量站起來。

### 道具

奶瓶（一人回復 50%）、小餅乾（兩人回復 30%）、小魚乾（元氣立刻全滿）。使用道具佔用該英雄的行動。每種上限 9 個。起始：奶瓶 ×2、小餅乾 ×1、小魚乾 ×1。

### 營地（每章第三站，三選一）

睡午覺（兩人回滿）／翻翻包包（奶瓶 ×1、小餅乾 ×1）／練習丟積木（經驗值 +15）。升級也會回滿血，所以「差一點升級就去練習」是刻意留下的小算計。

### 章節地圖（探索）

每一章是一條可以左右走動的橫向場景（`WORLD_WIDTH = 3` 個螢幕寬）。玩家按住「往左／往右」或直接點場景讓寶咖咖走過去，摩卡貓跟在後面，鏡頭跟著捲動；遠景裝飾（雲、圍籬、星星）用不同的 `depth` 捲得比較慢，走起來有前後層次。四站的搗蛋鬼、營地與頭目就站在路上（`world.stops`），碰到目前這一站就會「！」一聲進入戰鬥或營地；打贏的位置留下一顆星，休息過的營地變灰。靠近時搗蛋鬼會冒出對話泡泡，頭目說牠的台詞。

每章地上放了 1～2 個道具（`world.pickups`），走過去就撿；第二章與第五章各有一個藏在起點左邊，獎勵往回走看看的人。撿過的道具記在 `run.picked`，輸了重打不會再出現一次。

地圖上的位置不存檔：進入地圖時寶咖咖出現在起點，或上一站的右邊一點。

### 升級

累積經驗 `[0, 30, 80, 150, 240, 360]` 對應 Lv1～6。以固定的戰鬥經驗值計算，Lv2 落在第一章頭目前後、Lv4 在第三章、Lv6 在第五章中段；第六章是滿等打最終頭目。

## 3. 內容

六章沿用找找看的六個場景色票與背景裝飾，每章兩種小怪與一個頭目，共 18 種搗蛋鬼、18 張新 sprite。

| 章 | 場景 | 小怪 | 頭目（台詞） |
|---|---|---|---|
| 1 | 客廳大騷動 | 灰塵球、髒襪子怪 | 積木巨人「誰敢亂動我的積木！」 |
| 2 | 院子的地底下 | 蚊子、蝸牛 | 地鼠大王「這個院子的土都是我的！」 |
| 3 | 公園的天空 | 搶食鴿子、風箏怪 | 烏鴉老大「嘎嘎！亮晶晶的東西都歸我！」 |
| 4 | 熱鬧市場保衛戰 | 螃蟹、蘋果滾滾 | 大魚王「小魚乾？想都別想！」 |
| 5 | 海邊的八爪大戰 | 搶食海鷗、水母 | 大章魚（帶一隻海鷗）「八隻手打你們兩個，太簡單了！」 |
| 6 | 夢境的盡頭 | 小睡魔、惡夢雲 | 打呼嚕大王「呼嚕——這個娃娃……是我的了……呼嚕——」 |

每個敵人有 3～6 招固定循環，四種招式類型：攻擊（單體／全體）、防禦（下次受傷減半）、蓄力（什麼都不做，用來預告下一招）、回復。內容規則（`validate.ts`）：蓄力後面一定是攻擊；頭目節點一定含頭目；每章最後一站一定是頭目。

故事：睡前安撫娃娃被打呼嚕大王搶走，兩個人一路追到夢裡；最後發現大王只是想找人一起睡。序章與每章結尾各一頁繪本文字，結局頁全家一起睡著。

## 4. 平衡方法

不用感覺調數字。`src/quest/engine/sim.ts` 有三個腳本玩家跑完整流程（`npm run sim [seeds]`）：

- **smart**：會補血、用道具、只在「蓄力後的大招瞄準自己」時防禦
- **casual**：會補血、用道具，從不防禦
- **naive**：只會攻擊，營地永遠選練習

目前數字下（300 個種子）：smart 與 casual 都能通關，平均輸 0～0.06 次；naive 從第三章頭目開始輸（第三章 38%、第五章 100%），沒有一個種子能通關。小怪戰 2～8 回合，頭目戰 5～11 回合。`sim.test.ts` 把「會補血的人打得完」與「不補血的人打不完」兩件事釘成測試，改怪物數字時會在 CI 爆掉。

## 5. 架構

```
src/
  App.tsx                      # useRoute() → Hub / FindGame / QuestGame
  shared/
    route.ts                   # hash 路由：#/、#/find、#/quest；沒有 router 套件
    storage.ts                 # loadJson / saveJson：壞資料一律退回預設值
    audio.ts                   # WebAudio 合成音效，兩個遊戲共用
  art/                         # 兩個遊戲共用的色票、sprite 註冊表、背景、Scene 元件
    types.ts                   # SpriteName / PaletteName / Placement
    Scene.tsx                  # 背景 + 裝飾 + 覆蓋層；placementStyle()
    sprites/foes*.tsx          # 18 個搗蛋鬼，依章節分檔
  hub/HubScreen.tsx            # 遊戲選單，讀兩份存檔顯示進度
  find/                        # 找找看，原封不動搬進來（game/ screens/ components/）
  quest/
    QuestGame.tsx              # useReducer(questReducer) + 存檔 effect
    engine/
      types.ts                 # 資料契約
      heroes.ts foes.ts chapters.ts   # 內容（TS 常數）
      battle.ts                # 戰鬥狀態機：startBattle / battleStep / foeIntent
      quest.ts                 # 流程狀態機：章節、營地、勝利、失敗、升級
      save.ts                  # localStorage key 'baokaka.quest'
      validate.ts              # 內容規則
      sim.ts                   # 平衡模擬器
    screens/                   # Title / Story / Chapter（橫向探索地圖）/ Battle / Camp / Victory / Defeat / Ending
    components/                # Bar（血量／經驗條）、PartyPanel
scripts/sim.ts                 # npm run sim
```

### 純函式戰鬥引擎

`battleStep(battle, action)` 是純函式：不碰時間、不碰 `Math.random`。亂數用 mulberry32，種子放在 `Battle.seed`，每次擲骰都把新種子寫回去，所以**同一個種子重播出一模一樣的戰鬥**，測試不需要 mock，StrictMode 重複呼叫 reducer 也不會產生兩個結果。開新戰鬥時的種子由 UI 用 `Date.now()` 帶進 action。

敵人回合被拆成一個一個 `tick`：`phase = { kind: 'foe', index }`，UI 每 850ms 送一個 tick，每個敵人的動作才有時間被看見。引擎不排程，UI 只是時鐘。

每一步產生 `events`（誰出招、誰掉多少血、誰嚇到、誰倒下、元氣增減），UI 靠 `Battle.step` 當 key 把它們變成飄字、晃動與音效；引擎不知道畫面存在。

### 存檔

`{ run, sound }`，在 `run` 或 `sound` 改變時寫入。戰鬥中不存檔：重新整理會從該站重打，HP 是進站時的值。破關時 `run` 立即重設為新局並標記 `cleared: true`（不是在結局頁重設），所以結局頁關掉分頁再回來不會卡在不存在的節點。讀檔驗證章節與節點存在、等級在範圍內，任何不對就當新局。

### 與找找看的關係

找找看的程式與存檔 key（`baokaka.progress`）完全沒動，只是搬進 `src/find/`，並在標題頁與地圖頁多了「回遊戲選單」。共用的部分（色票、sprite、`Scene`、音效、儲存）搬到 `src/art` 與 `src/shared`。`SpriteName` 仍是一個字串聯集，註冊表是 `Record<SpriteName, Sprite>`，所以哪個遊戲引用了不存在的圖案都在編譯期爆掉。

## 6. 畫面

- **遊戲選單**：兩張大卡片，各顯示進度（「已完成 3 / 6 個地方」、「第 2 章 · 等級 3」）。勇者團掛「新遊戲」標籤。
- **標題**：有存檔時顯示「繼續冒險」與需要二次確認的「重新開始」。
- **章節地圖**：橫向捲動場景（見 §2 章節地圖）、目前第幾站、一行提示（「往右走，去找搗蛋鬼」「頭目就在前面……小心！」）、「往左／往右」兩顆大按鈕（按住即走，也可點場景走過去，電腦用方向鍵）、精簡隊伍面板（等級、兩條血條、道具）。
- **戰鬥**：正方形場景（敵人在上、英雄在下、意圖泡泡、血條、飄字），元氣五顆點，動作面板（三欄招式格：名稱、元氣點數、一行說明；道具子選單），最下方一行戰報。選單體招式而場上有兩個以上敵人時進入「點一個敵人」模式，敵人變成可點的虛線框；抱抱與奶瓶則選夥伴。頭目戰第一回合的戰報列顯示頭目台詞。
- **勝利**：經驗值、升級（等級變化、新招式）、掉落。**失敗**：說明規則（回本章開頭、經驗與道具保留）並提示看意圖與防禦。

UI 規則沿用前作的色票與 `BigButton`，但不受長輩規範（最小字級、64px）約束：戰鬥面板用 12～16px 的說明文字與 3 欄格線，才塞得進一個手機畫面。

## 7. 測試

- `battle.test.ts`（30）：亂數決定性、招式合法性、目標檢查、防禦減半、嚇到跳過、補血復活、道具、回合順序、跳過死亡敵人、勝負判定、敵人防禦／蓄力／回復／全體攻擊、瞄準與備援目標
- `quest.test.ts`（24）：升級與回滿、勝利結算（HP／道具／掉落／倒下站起 25%／上限 9）、營地三選、畫面流程含破關重設與失敗重試、地上道具只撿一次且輸了不重生
- `save.test.ts`（10）：壞 JSON、不存在的章節／節點、欄位型別、私密模式讀寫例外、舊版存檔補上 `picked`
- `content.test.ts`（6）：內容規則、每個敵人都出場、頭目血量遞增、技能表、每章地圖的站點與道具
- `sim.test.ts`（4）：平衡回歸（見 §4）

加上前作 49 個，共 123 個測試。地圖上的走動、鏡頭與碰撞是 UI 層的 `requestAnimationFrame` 迴圈，不寫單元測試，用瀏覽器實跑驗收。
