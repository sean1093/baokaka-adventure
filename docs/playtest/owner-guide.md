# M1 試玩：給你的簡短說明

M1（序章＋台北車站，10 頁）已經可以完整玩一遍。接下來要請你帶家人試玩，再由你決定要不要繼續做第 2～10 章（go / no-go）。這一頁是重點整理，詳細步驟在 [`README.md`](README.md)（英文）。

## 1. 怎麼玩

- 網址（有開試玩紀錄）：**https://sean1093.github.io/baokaka-adventure/#/?debug=metrics**
- 畫面最上方中間會有一個深色小標籤，例如「● 0-3 1:12」和一顆 ★。只有觀察的人用：
  - 點 **★**：標記「這一刻值得記」（笑了、卡住、問問題），報告裡會列出時間和頁數。
  - 點**標籤**：打開紀錄，可以 **複製 Copy**、**下載 Save**、**清除 Clear**（按兩下）。打開紀錄時，遊戲會暫停。
- 紀錄只存在**這支手機**，不會上傳。網址裡沒有 `debug=metrics` 就完全不記錄。
- 每位試玩者開始前：設定 →「重新開始」（按住 3 秒），讓他從頭玩；再把上一位的紀錄複製出來、清除。
- iPhone 請把側邊的**靜音開關打開成有聲**（靜音模式下網頁沒有聲音），音量約 70%。手機鎖定直向。

## 2. 試玩怎麼進行

- 人數：至少 **1 位阿公阿嬤、1 位 4～8 歲小朋友、2 位爸爸媽媽**，一位一位玩，每位約 10～20 分鐘。最後可以再全家一起自由玩。
- 紀錄只寫角色（G1、C1、P1、P2），**不寫名字**。給家人看的說明：[`guide-zh.md`](guide-zh.md)。
- 把手機交給他時只說：「這是寶咖咖的新遊戲，你玩玩看。」之後**不教、不提示**。
- 卡住**超過 2 分鐘**又沒按「提示」→ 記下來（這一關沒過），只說「下面的按鈕都可以按按看」；**4 分鐘**再說「可以按『提示』喔」。
- 在 1-2 和 1-4 問「你覺得他會去哪裡？」，小朋友玩完序章後問「寶咖咖都會往哪裡爬？為什麼？」。題目照 [`sheet.md`](sheet.md) 的 B 部分唸。
- 每位試玩者一張觀察表：[`sheet.md`](sheet.md)（英文表格，打勾為主）。

## 3. 要看的重點

**過關標準（GDD §8）**
- 阿公阿嬤：0-1 不靠任何幫忙 **90 秒內**完成；整個序章 **12 分鐘內**、「提示」最多用 **2 次**。
- 小朋友：玩完序章能用自己的話說出「他會去他想要的東西那邊」。
- 預測他會去哪裡：**7 成以上**猜對。
- 第一章用到「提示」第 3 層（直接示範）：每人**最多 1 頁**。
- 摩卡第一次推東西（0-3）、第一次故意讓他哭（0-4）：4 個人裡至少 **3 個**笑出來或有反應。
- 至少 **1 個人**主動重玩某一頁去拿淘氣或土地公貼紙。
- 第一章每頁平均 **1～3 分鐘**；**沒有人**卡超過 2 分鐘又不用提示。

**工程師留下的觀察點**（完整清單在 README §6、觀察表 C 部分）
- 聲音：在真手機上第一下點擊後有沒有聲音；音量合不合適；「要！要！」會不會吵；哭聲是不是可愛不讓人難過；音樂盒聽 10 頁會不會膩。
- 一開始字很多（序章卡片＋0-1 的開場白）；台詞要**點台詞本身**才會往下；章節卡和「嗶！」字卡沒有「點一下繼續」的提示。
- 序章的教學手在寶咖咖伸手 **4 秒**後出現，對長輩是太快還是剛好？
- 每頁之間的貼紙卡（約 2.4 秒）玩到後面會不會覺得拖。
- 0-4：先拉開窗簾的話，他會一直伸手要門外的珠子、不會哭，要想到把窗簾拉回去。
- 1-1：「拉」的搖晃紙條會不會被當成玩具（它只給淘氣貼紙）；廣播姊姊的對話框蓋住吊環和行李架；紙片風的背包客放在動漫風的寶咖咖旁邊順不順眼。
- 1-4：沒有提示的話，想不想得到要「趁他在轉盤上時再轉一次」。
- 1-5：會不會發現在電梯裡**點摩卡**可以再按一次按鈕。
- 1-6：看不看得出鴿子也想吃雞腿。
- 老玩家有沒有注意到封面上「寶咖咖的新冒險開始了！」的告別卡。

我先用自動化跑過一遍（[`ai-playtest.md`](ai-playtest.md)），10 頁都能順利玩完，也列出可能卡住的地方，請試玩時特別留意。

## 4. 怎麼回報

1. 每位試玩者：在紀錄裡按 **複製 Copy**，貼到他那張觀察表的 D 部分（或傳給我下載的檔案）。
2. 觀察表拍照或打字都可以，直接留言在 issue [#110](https://github.com/sean1093/baokaka-adventure/issues/110) 或交給工程師整理進 [`m1-results.md`](m1-results.md)。
3. 最後請你寫下結論：**go**（開始做第 2～10 章）或 **no-go**（先修什麼）。沒過的每一項都會開成 issue，修好再往下做；你的決定會記在 `docs/project/decisions.md`。
4. 簽核之後才會刪除舊的 RPG（#111）並開始 M2。
